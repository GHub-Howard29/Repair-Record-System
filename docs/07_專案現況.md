# 07_專案現況

> 最後更新：2026-08-12
>
> 本文件僅保留專案目前可用功能與後續工作，不記錄功能修改過程。

## 已完成功能

### 帳號與資料同步

- 支援 Google OAuth 登入並同步建立 Firebase Authentication session。
- 維修紀錄文字資料可同步至 Firestore；離線資料與同步失敗工作會保留，恢復連線後可再次同步。
- 維修照片可經 Firebase Functions 上傳至 Google Drive，並保存附件 metadata；新增、刪除或更換會先立即更新本機畫面，再由單工背景佇列同步雲端，使用者不必等待上傳完成即可繼續操作。刪除附件時會將儲存與附件操作鎖定至少 1 秒，避免連續誤刪；背景同步不延長鎖定時間。同步結果以附件版本與操作識別碼安全合併；上傳途中刪除或換版時會自動清理過期的 Drive 檔案。Firestore 即時監聽會在本機有待同步工作時保留最新本機版本，避免舊雲端快照覆蓋連續操作。附件同步狀態以中文顯示；已有雲端附件可使用本機預覽或 Drive 縮圖備援。
- 同步區會依實際待處理工作顯示維修文字、照片上傳及／或照片刪除項目；無待處理工作時僅顯示「所有資料已同步」，已完成驗證。
- 已完成案件依 Firestore Rules 限制授權帳號讀寫；系統不提供刪除維修紀錄功能。

### 維修紀錄管理

- 可新增、編輯、查詢維修紀錄；同一製造號碼不可同時存在兩筆未完成案件。
- 收到日期、回送地點、製造號碼為必填；製造號碼固定為 `NIS-` 加 12 碼英數字，會自動轉為大寫。
- 填寫送回日期後，系統會先檢核收到日期、回送地點、製造號碼、客戶姓名、機器屬性、維修日期、故障分類及維修內容或備註；通過後案件與附件才會鎖定為唯讀。缺少資料時會以無綠色背景的醒目紅色提示文字告知，且不可封存；已完成驗證。
- 四個日期欄位（收到、出貨、維修、送回）支援單一輸入框手動輸入 `YYYY/MM/DD` 與日曆選擇；從尾端輸入時自動補分隔符號，在中間編輯時保留原字元位置，可單獨刪除或更換任一數字。進入編輯時會保留修改前的有效值；首次完成有效輸入後，即使維修單尚未儲存，也會立即升級為同一次編輯的復原基準。按 Esc，或離開欄位時內容不完整、格式錯誤或不是實際存在的日期，會自動復原。此行為連同查詢開始／結束日期，共 6 個日期欄位均已完成本機瀏覽器回歸與正式站實機驗證。按 Enter 時僅在日期完整有效才跳至下一個可輸入欄位；不合法日期會停留原欄並顯示提醒，核取、單選、附件與文字區塊不納入導覽。
- 查詢的開始／結束日期共用相同單一輸入框與日曆選擇元件，不顯示重複的原生日期欄位；已完成實機驗證。
- 窄版頁面只要離開頁面頂端，就會在右下角顯示固定懸浮的回頂按鈕；按鈕不隨內容捲動，點擊後平滑回到頁首，寬版與頁面頂端均不顯示。
- 機器屬性選項為門市客人、網購、展示機；查詢卡片顯示回送地點／客戶名稱／機器屬性。
- 支援故障分類、故障零件複選、零件收費、維修內容、備註、歷史維修摘要與附件照片管理。

### 保固與收費

- 保固期判斷位於故障分類右側，以收到日期與出貨日期相差是否超過 `365 + 30` 天判定保固期內或超過保固期；日期不足或不合法時顯示尚待確認。
- 保固判斷為即時計算，適用於既有紀錄，不會自動改寫備註或收費。
- 檢修測試費、運費與零件費可個別設定；系統自動計算維修總金額。

### 查詢、匯出與介面

- 支援依姓名、製造號碼、回送地點、收到日期區間與更換零件查詢；更換零件選項沿用故障零件清單並比對歷史紀錄的故障零件，可切換維修中／已完成狀態。
- 可匯出單筆 PDF；PDF 包含維修資料、保固期判斷、收費內容與附件清單（有附件時）。檔名為 `維修報告_YYYYMMDD_客戶名稱.pdf`，日期使用送回日期；電腦使用瀏覽器列印另存，LOGO 直接內嵌於列印 HTML，並等待圖片解碼完成後才開啟預覽；系統字型等待上限縮短為 250ms，開始匯出時會立即顯示準備訊息，首次匯出速度與彩色 LOGO 顯示已通過正式站實機驗證。手機／平板以逐頁 2 倍解析度 Canvas、JPEG 品質 0.98 產生高品質 A4 實際 PDF 檔後開啟系統 App 選擇面板，可避免長內容輸出空白 PDF。PDF 標題上方以原始 NICE GREEN 彩色 LOGO 與置中的「庭茂農業生技股份有限公司」組成水平群組，LOGO 位於左側且無外框；公司名稱使用標楷體候選字型，字級與維修紀錄標題相同。手機端已避免標題被第一頁裁切，附件清單會另起一張 A4 頁，照片保留原始長寬比例且不會與說明跨頁切割；品牌排版與手機高解析度輸出均已驗證。
- 可依搜尋結果匯出 Excel，包含「維修紀錄」與「收費明細」工作表。收費明細會排除金額為 0 的項目。
- Excel 使用中文機器屬性與維修總金額欄位；有資料的儲存格具四周細框線。維修內容固定寬度 47、備註固定寬度 27，文字靠左、垂直置中並交由 Excel 自動換行及調整列高。
- 支援桌面工作台與手機窄版功能選單；已建立 PWA manifest、service worker 與應用程式圖示。手機窄版的附件、收費摘要、歷史維修及功能選單捲動與操作均已驗證。
- 寬螢幕工作台的維修紀錄列表與新增／編輯區各自提供獨立垂直捲動，滑鼠滾輪停留在哪一欄就只移動該欄，也可拖曳欄位捲軸；螢幕寬度 1120px 以下維持原本整頁捲動，不顯示欄位專屬捲軸。

### 開發與部署維護

- 正式前端部署於 `https://repair-record-system.vercel.app/`；GitHub 作為原始碼儲存庫，push 後由 Vercel 自動建置及發布。Vite 以根路徑 `/` 建置，GitHub Pages workflow 僅保留手動觸發作為回復選項。
- PDF／Excel 匯出模組只在使用者操作時動態載入；Firebase 已拆分 Auth 與核心 chunk。Excel 的 `xlsx-js-style` chunk 約 863 kB，但不屬於首屏載入資源。
- 根目錄與 `functions/` 各自維護必要的 `node_modules`；Functions 不再依賴根專案，避免產生指向根目錄的 Junction。
- 若暫時不需修改、檢查或部署 Firebase Functions，可移除本機 `functions/node_modules` 釋放空間；重新使用前執行 `npm run functions:install` 即可。
- 附件上傳、刪除與預覽 Functions 均已部署至 `asia-east1`；附件異動即時同步已完成三台設備的新增、更換、刪除實機驗證。
